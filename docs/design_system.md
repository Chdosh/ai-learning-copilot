# AI Learning Copilot 设计系统

> 本文档回答每一处设计的"为什么"。任何 UI 决策必须能从本文档推导出来；
> 无法推导的决策不允许出现在代码里。实现规则：**代码只引用 token，禁止裸值。**

## 0. 决策来源（三个）

每个设计值必须能追溯到以下之一：

| 来源 | 内容 | 例子 |
|---|---|---|
| **设计规范** | clean 风格 + 通用 UI/UX 设计原则 | 主色 `#3B82F6`、8pt 网格 |
| **内容度量** | 由实际内容/人体物理推导 | 行宽 30-45 字 → 会话流宽度 |
| **使用频率** | 高频功能占主导空间，低频收敛/折叠 | 操作菜单、参考抽屉 |

优先级：**可用性 > 一致性 > 美观**。任何"好看"不能牺牲可读和可点。

---

## 1. 色板（10 个色，31 → 10）

规则：**每个色只能有一个职责**，同类职责禁止第二种色。

| Token | 值 | 对比度(白底) | 为什么是这个值 |
|---|---|---|---|
| `PRIMARY` | `#3B82F6` | 3.5:1 | clean 规范主色；作为"唯一强调色"（UI 组件 3:1 达标，正文不用它）；亮度中等、色相中性偏蓝，色盲友好 |
| `PRIMARY_DARK` | `#1D4ED8` | 5.7:1 | 主色按下态：按压反馈必须比常态"更实"，加深 = 物理下压感 |
| `PRIMARY_HOVER` | `#60A5FA` | 2.6:1 | 悬停态：提示"可点"但**不抢**主按钮注意力，只用于边框/描边色 |
| `PRIMARY_SOFT` | `#EFF4FF` | — | 选中态底：主色 6% 浓度，整片浅底表示"当前所在"，不刺激 |
| `TEXT` | `#111827` | 14.7:1 | clean 规范主文字；正文必须>4.5:1，取最高一档保证任何环境可读 |
| `TEXT_SECONDARY` | `#344054` | 7.8:1 | 次级文字（字段标签、说明）：比正文轻一档，仍远超 AA |
| `MUTED` | `#667085` | 4.7:1 | 元数据（时间戳、计数）：**刚好压线过 4.5:1**——可读但视觉主动退后 |
| `DISABLED` | `#98A2B3` | 2.4:1 | 禁用态：故意低对比——不可交互的东西不该被眼睛抓住 |
| `BORDER` / `BORDER_LIGHT` | `#E4E7EC` / `#EEF1F4` | — | 结构线/分隔线，1px 细线不做焦点，只做分组 |
| `BG` / `CARD` | `#F6F7F9` / `#FFFFFF` | — | 页面底色比卡片低一档明度，卡片靠明度差浮出（不用阴影区分层级，扁平化） |
| `DANGER` | `#DC2626` | 4.0:1 | 唯一危险色；系统中第三种可感知色（蓝=主、绿=成功 `#16A34A`、红=危险），**红只用于删除类** |

规则：悬停/按下/禁用/选中四个状态色的明度关系**全局固定**（hover 亮于常态、pressed 深于常态、disabled 灰、selected 浅底），任何按钮不得另起一套。

## 2. 字号（8 → 4 级）

| Token | 值 | 用途 | 为什么 |
|---|---|---|---|
| `FONT_MICRO` | 12px | 元数据/状态标签 | 规范：12px 只用于 badge/短标签；本应用最低级信息就是时间戳和计数 |
| `FONT_BODY` | 13px | 正文/按钮/列表 | 桌面**密度型** UI（typography-principles：UI 14-16 密度驱动取低端）；窗口 855px 要容纳三栏信息；提供 A+/A- 全局缩放（11-17）兜底可读性 |
| `FONT_TITLE` | 16px | 页头/区域标题 | 正文 × 1.23（规范 1.125-1.25 模块比），一档跳变，肉眼可分 |
| `FONT_HEADING` | 20px | 卡片主标题/详情主词 | 再跳一档（1.25），两级标题差距陡峭（层级靠跳变不靠绝对值） |

层级上限 4 级：micro < body < title < heading，**禁止第 5 级**（如 24/36px 正文）。

---

## 3. 圆角（7 → 4 级）

规则：**圆角是"容器层级"的语言**——值越大表示表面越大、越"软"。

| Token | 值 | 用在 | 为什么 |
|---|---|---|---|
| `RADIUS_SM` | 6px | 输入框 | 输入是"内部填充"的控件，圆角最小避免与内容抢视觉 |
| `RADIUS_MD` | 8px | 按钮、列表项 | 交互件基准值，落在 8pt 网格上 |
| `RADIUS_LG` | 12px | 卡片 | 大表面需要更大圆角软化边缘，与 8px 按钮形成层级差 |
| `RADIUS_PILL` | 16px | chips/标签 | 胶囊形 = "可切换标签"的形状语义，与其他按钮用**形状**区分而不是颜色 |

为什么不用 10px/14px：非网格值没有理由，禁止。

---

## 4. 间距（4pt 网格，4 档）

| Token | 值 | 用在 |
|---|---|---|
| 微 | 4-8px | 组内（label↔输入框、图标↔文字、按钮组内） |
| 小 | 12-16px | 同组兄弟元素、卡片内 section |
| 中 | 24px | 卡片之间、区块之间 |
| 大 | 32px | 页头→内容、大区块分隔 |

规则（spacing-principles）：**外层 padding > 内层 gap**（卡片内边距 ≥ 16，卡片间距 ≥ 24）；
每个页面至少出现 3 个间距档位，所有间距必须落在 4pt 网格（4/8/12/16/20/24/32/48）。

## 5. 组件规范（尺寸 = 理由）

### 5.1 按钮（4 个等级，1 个形状系统）

| 等级 | 样式 | 高度 | 为什么这个大小 |
|---|---|---|---|
| **Primary**（主操作） | 主色实底白字 | 32px | 每页**唯一**首要动作；实底 + 全饱和色 = 全屏唯一高亮 |
| **Ghost**（次操作） | 白底灰边 | 30px | 默认按钮；1px 边框传达"轻量可点"，不饱和 |
| **Danger**（危险） | 红字浅红底 | 30px | 危险操作不做大不做实底（ux-principles：危险按钮给次级样式 + 确认步骤）；颜色已足够警告 |
| **Mini**（微操作） | 同 ghost，padding 减半 | 28px | 低频（字号调节），缩小 = 降低视觉权重 |

所有按钮高度 ≥ 28px（桌面鼠标 Fitts 底线），触控场景用 40px 以上。
**主按钮比 ghost 高 2px**：唯一性靠尺寸差 + 颜色差双通道，防误触且一眼可辨。

### 5.2 输入框

白底、1px 灰边、`RADIUS_SM`、聚焦时边框变主色（唯一状态色通道，不用变色背景）。

### 5.3 卡片

白底 + 1px 灰边 + `RADIUS_LG`。层级靠**明度差**（白 vs 灰底）而不是阴影——阴影是弹窗专用（浮层语义）。

### 5.4 chips（筛选/方向）

胶囊形（`RADIUS_PILL`）、未选中白底、选中主色实底。形状即语义：**胶囊 = 可切换**，圆形按钮 = 动作。

### 5.5 列表

行高 40px（桌面触控 44 底线放宽一格）、选中主色浅底 + 主色文字、无边框（proximity 分组）。

### 5.6 导航

左对齐无边框、选中浅底。导航是"位置指示器"不是按钮——不做立体效果。

## 6. 布局（每个区域的位置和大小 = 理由）

### 6.0 窗口骨架（855×550 不变）

```
┌──────────┬─────────────────────────────┐
│ 侧栏 144  │ 页头 52                     │
│ (恒定)   ├─────────────────────────────┤
│          │ 页面内容（弹性 + 滚动）        │
│          ├─────────────────────────────┤
│          │ 状态栏 32（全局反馈）          │
└──────────┴─────────────────────────────┘
```

| 区域 | 尺寸 | 理由 |
|---|---|---|
| 侧栏 | 144px | 4 项导航 + 字号 + 统计卡；导航是**恒定结构**，固定宽度（ui-principles：侧栏固定、主区弹性）；144 = 18×8 |
| 页头 | 52px | 标题 16px + 上下 16px padding + 状态 |
| 状态栏 | 32px | 单行反馈，不参与层级 |

### 6.1 学习概览（默认落地页）

```
┌─────────────────────────────────────────────┐
│ 学习概览      [学习方向:XX]       [筛选] [操作▾]│  ← 页头：标题在左(锚点)，操作在右(菜单化)
├──────────┬──────────────────────────────────┤
│ 会话列表  │ 会话流（阅读面, ≥455px）           │
│ 216px    │ 原图缩略(内联, 点看大图)            │
│ 搜索+chips│ 原文→翻译/解释/术语→追问流          │
│ 列表      │ [▸ 术语·标签] ← 底部抽屉(渐进披露)  │
└──────────┴──────────────────────────────────┘
```

| 决策 | 理由 |
|---|---|
| 左列表 216px | 两行文本预览 ≈ 28 字/行，216 = 27×8；列表是"索引"，宽度由内容度量决定 |
| 会话流 ≥455px | 中文行宽 30-45 字 × 14px ≈ 420-630px；855−144−216−边距 = **487px ≈ 34 字/行**，落在标准区间（不需要加大窗口的数学依据） |
| 右栏取消 | 术语/标签/操作是**按需信息**（5% 时间），常驻=浪费；低频收敛进菜单/抽屉（渐进披露） |
| 操作在页头右 | 视觉链条终点（选完→读完→才操作），高频按钮左移、低频右移 |
| 原图内联在会话流顶部 | 截图是"这条记录的来源"，属于阅读流；尺寸按宽高比缩放，不写死 |
| 术语抽屉在底部 | 读完内容后的"提取"动作，位置跟随阅读终点（Zeigarnik：收尾动作就近） |

### 6.2 工作台（新建学习入口）

```
┌ 识别学习卡（上部）────────────────────────────┐
│ [截图识别|文本识别]  [开始截图翻译/输入框]        │  ← F 型扫描上部 = 动作区
├ 学习方向卡（下部）────────────────────────────┤
│ 当前：编程·学术论文            [详情▾]          │  ← 状态行(恒显) + 详情折叠
│ [通用][编程][生物]... ← 单行横滚 chips           │
└──────────────────────────────────────────────┘
```

| 决策 | 理由 |
|---|---|
| 识别卡在上 | F 型视觉流：动作在最上；截图是最高频操作，用 40px 主按钮（全应用最大） |
| 方向 chips 单行横滚 | 11 个方向在 711px 装不下两行才滚；chips 是**选择**不是**阅读**，横滚不损失效率 |
| 详情折叠 | "当前方向"是状态确认（一眼即够），背景要点是细节（展开才看）——渐进披露 |

### 6.3 术语本

```
表格(7) 列宽: 术语120 领域88 中文名120 关键词弹性 次数48 收藏48  │ 详情(4)
                                                                │ 名称(20px)
                                                                │ 领域·次数(内联)
                                                                │ [完整解释|当前例子] Tab
                                                                │ 收藏/编辑/删除
```

| 决策 | 理由 |
|---|---|
| 列宽按内容 | 术语名 6-10 字→120；领域 2-4 字→88；次数/收藏是数字→48；**关键词是长文本→唯一弹性列** |
| 解释/例子用 Tab | 两者互斥阅读（看解释时不看例子），Tab 节省垂直空间且语义明确 |
| 详情 35% | 详情是"从"，表格是"主"；但解释要读，所以最小 240px（≈ 17 字/行，够读） |

### 6.4 设置

7 个子页，全部内容包 QScrollArea（内容超一屏时滚动，**永不压缩**）；
表单单列（ux-principles：单列表单易扫读）、label 固定 130px（与最长标签"数据存储位置"同宽）。

### 6.5 弹窗（ResultWindow）

独立浮层：阴影（唯一使用阴影的地方=浮层语义）、380-760 弹性宽（内容自适应）、正文 13px。
操作行在底部（阅读终点）。

## 7. 反模式（禁止清单）

- 裸色值、裸圆角、裸字号出现在业务代码（必须走 token）
- 同一页面超过 1 个主色按钮
- 固定高度盒子堆叠（必须弹性 + 滚动）
- 两个不同含义的元素用同一样式（形状/颜色必须编码语义）
- 任何"感觉好"但没有本文档依据的数值
- 危险操作用大号实底红按钮（给次级样式 + 确认）
- 弹窗以外的界面使用阴影

---

## 8. 变更流程

新增/修改任何样式 → 先改本文档（含理由）→ 再改 theme.py token → 最后改业务代码。

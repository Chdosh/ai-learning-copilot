# 学习方向识别 × 学习建议 × 术语积累：自沉淀自学习闭环分析

> 分析范围：学习方向的自动识别，以及"学习建议（learning_tip）+ 术语积累（terms）"两个 AI 产出物如何形成"自沉淀、自学习"闭环，实现**拓展学习思维**（发散）与**固化知识**（收敛）。
> 姊妹篇：[terms_knowledge_base_analysis.md](terms_knowledge_base_analysis.md)（术语本/个人知识库，收敛侧）；本文档补发散侧与共享底座。
> 依据：`app/services/context_detector.py`、`app/services/categorizer.py`、`app/services/ai_client.py`、`app/services/prompt_builder.py`、`app/ui/workers.py`、`app/ui/result_window.py`、`app/ui/workbench.py`。

---

## 1. 诉求还原

> "学习方向的识别；学习建议和术语积累这两个方向自沉淀自学习，能迅速拓展学习思维和固化知识。"

拆成三个命题：

1. **方向识别是上游**：领域/场景认对了，学习建议才精准、术语解释口径才正确。
2. **两个产物飞轮**：学习建议负责"拓展思维"（发散），术语积累负责"固化知识"（收敛）。
3. **自沉淀自学习**：产出物不能是一次性的——要沉淀成结构资产，再反哺后续调用，越用越懂用户。

---

## 2. 现状盘点

### 2.1 三套并行的"方向"体系，互相不通

| 体系 | 位置 | 粒度 | 更新方式 |
|---|---|---|---|
| 学习方向 `contexts`（领域/场景/背景摘要/回答偏好） | `history_store.py` contexts 表 | 用户自定义 | 手动编辑，静态 |
| 领域/场景检测 | `context_detector.py` | 9 领域 + 5 场景 | **硬编码关键词表** |
| 内容分类 | `categorizer.py` | 6 类（报错/AI概念/Python/数据库/网络/文档） | **硬编码关键词表** |

三者的领域词表各不相同、语义重叠（如 `context_detector` 的"编程"和 `categorizer` 的"Python"），识别结果互相不校验、不融合。

### 2.2 方向识别的触发与继承逻辑

- `suggest_context`（`context_detector.py:150`）：仅当粘贴文本 ≥120 字且有信号时才**建议**学习方向（工作台入口）。
- 截图流程（`workers.py`）：**不对 OCR 文本做方向识别**，domain 直接继承"当前学习方向"整批传给 `upsert_terms`。
- 即：方向识别只在"长文本粘贴"场景存在，最核心的截图场景反而缺失。

### 2.3 学习建议（learning_tip）：一次性产物

- 来源：AI JSON 的 `learning_tip` 字段（`prompt_builder.py:51`，"仅在确有补充价值时填写"）。
- 去向：存进 message JSON（`workers.py:299`），在结果窗展示（`result_window.py:662 _set_tip`）。
- **没有独立表、没有状态（采纳/忽略/完成）、没有聚合视图、没有任何反哺**。看完即消失。

### 2.4 背景摘要（summary）：静态锚点

- `contexts.summary` 是解释助手理解领域的锚点（`prompt_builder.render_context_block`）。
- 唯一的自动生成能力 `AIClient.generate_summary`（`ai_client.py:182`）只用于**压缩用户粘贴的长文本**，是一次性动作。
- 系统**从不**把"用户新学到的内容"沉淀回 summary——学习方向不会随使用而生长。

## 3. 问题诊断

1. **方向识别不生长**：关键词表硬编码，用户从 Python 转向 Rust 或新领域时，识别体系原地踏步；三个体系词表重复维护、互相矛盾。
2. **截图无识别**：最高频场景反而跳过识别，domain 靠"继承"，用户忘了切换学习方向时整批术语和解释口径全错。
3. **学习建议无生命周期**：给出即终点。没有采纳率、没有到期提醒、没有按方向聚合的"建议清单"，无法形成"建议 → 行动 → 反馈"的回路。
4. **无自沉淀**：学习方向的背景摘要不知道用户最近学了什么；AI 每次都从零理解用户，上下文没有随使用累积。
5. **无拓展**：没有"延伸阅读/相关概念"类建议，学习思维停在单条截图内，知识面不扩张。

---

## 4. 目标形态：双飞轮模型

```
飞轮一 · 拓展学习思维（发散）
┌──────────────────────────────────────────────┐
│ 截图/文本 ─→ 方向识别(画像) ─→ AI解释 + 学习建议 │
│   ↑                              ↓          │
│ 背景摘要自更新(自沉淀) ←── 采纳/完成(状态回流)  │
│   ↑                              ↓          │
│  └── 更准的方向与建议 ←── 延伸/关联推荐(拓展) ──┘ │
└──────────────────────────────────────────────┘

飞轮二 · 固化知识（收敛，见姊妹篇）
┌──────────────────────────────────────────────┐
│ 截图/文本 ─→ 方向识别(画像) ─→ 术语提取         │
│   ↑                              ↓          │
│ 掌握度/复习 ←── 间隔重复 ←── 分级/去噪/回链     │
└──────────────────────────────────────────────┘

共享底座：方向画像（两轮质量的共同上限）
```

**核心洞察**：方向识别是双飞轮的公共基础设施。识别差 → 建议偏、术语口径错，两个飞轮同时劣化；识别准 → 飞轮自增强（识别 → 建议/术语 → 沉淀 → 更准的识别）。

## 5. 关键设计

### 5.1 方向画像：识别输出的升级（底座）

输出从"一个标签"升级为"画像 + 来源 + 置信度"：

```python
{
  "domain": "编程",
  "scene": "报错信息",
  "confidence": 0.82,
  "candidates": [("编程", 0.82), ("数据库", 0.45)],  # top-N 备选
  "source": "keywords"   # keywords | user | ai | inherited
}
```

- 截图流程接入：OCR 完成后对文本做 `detect_domain/detect_scene`（纯本地，零成本）。
  - 与当前学习方向一致 → 继承（现状）
  - 冲突且置信度够高 → 结果窗轻提示"这条像是『数据库』方向，已按当前方向解释，可一键切换"
  - 低置信 → 保持当前方向
- `categorizer` 的 6 类内容分类并入画像（一张截图可以有 domain + category 两个维度），两套词表逐步归一。
- 画像同时作为术语 `domain` 字段的缺省值来源（见姊妹篇 5.4），替代"整批继承"。

### 5.2 方向体系自进化（自学习，本地优先）

| 阶段 | 机制 | 成本 |
|---|---|---|
| 1（0.7） | 从用户 capture 的 tags/terms/category 统计高频词，与内置关键词表合并打分（纯本地统计） | 零 API |
| 2（0.8） | 自定义学习方向支持"领域关键词种子"，用户给新领域（如 Rust）喂 5–10 个种子词即生效 | 零 API |
| 3（1.0） | 对低置信/无方向的历史记录做 LLM 批量标注回填（手动触发） | 可控 |

红线：识别永远可被用户一键纠正；纠正记录（capture.domain 的用户改写）作为阶段 1 统计的正/负样本。

### 5.3 学习建议结构化：`learning_tips` 表

```sql
CREATE TABLE learning_tips (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    capture_id INTEGER NOT NULL REFERENCES captures(id) ON DELETE CASCADE,
    context_id INTEGER,                          -- 所属学习方向，可空
    domain     TEXT NOT NULL DEFAULT '',
    content    TEXT NOT NULL,
    tip_type   TEXT NOT NULL DEFAULT 'followup', -- followup|reading|concept|review
    status     TEXT NOT NULL DEFAULT 'pending',  -- pending|done|ignored
    created_at TEXT NOT NULL,
    done_at    TEXT NOT NULL DEFAULT ''
);
CREATE INDEX idx_learning_tips_status ON learning_tips(status, domain);
```

- `tip_type` 四类：
  - `followup`：建议继续追问什么（纵向深入）
  - `concept`：建议了解的相关概念（**横向拓展**，与 5.5 关联推荐打通）
  - `reading`：延伸阅读/动手尝试
  - `review`：提醒复习本方向已学过的相关术语（与飞轮二衔接）
- 写入点：workers 在存 message 时同步写 `learning_tips`（`learning_tip` 非空才写）。
- UI：工作台新增"学习建议清单"视图——按方向/状态分组，勾选完成/忽略；结果窗加"加入建议清单"开关。
- 自学习回路：`done` 的建议在阶段 3 用于学习路径统计（哪些建议被采纳 → 哪些类型值得多给）。

### 5.4 背景摘要自沉淀（自沉淀核心）

`summary` 从"用户手写的静态锚点"升级为"随学习生长的画像"：

```
触发（手动或达到阈值：当前方向下新增 N 条记录）
  → 取增量（新记录的 explanation + terms + done 的建议）
  → AI merge：合并进现有 summary（复用/改造 AIClient.generate_summary）
  → 用户确认（diff 预览，默认不静默改写用户数据）
  → 更新 contexts.summary + updated_at
```

- 0.7 只做**手动触发**（工作台"把最近 N 条沉淀进当前方向"按钮 + diff 预览），风险最低。
- 0.8 做阈值提醒（新增 ≥5 条记录时托盘提示"当前方向有 5 条新内容，是否沉淀？"），仍保留人工确认。
- 效果：AI 解释时自动知道"你最近在学 X、已掌握 Y"，学习建议与术语口径随之进化——这就是"越用越懂你"。

### 5.5 关联推荐（拓展学习思维）

- 短期（0.7）：`concept` 类学习建议——prompt 规则增加"确有关联概念时，learning_tip 给出 1 个值得延伸了解的概念及其一句话理由"。
- 中期（0.8）：与姊妹篇的 embedding 相关术语推荐打通——"你收藏了过拟合，同方向还有梯度下降/正则化未收藏"。
- 目标：从"看懂一条截图"变成"从一条截图长出一条学习路径"。

### 5.6 与术语飞轮（姊妹篇）的衔接点

| 共享点 | 机制 |
|---|---|
| 方向画像 | 术语 per-term domain 缺省值、术语解释口径（prompt 层） |
| 建议 → 复习 | `review` 类建议直接指向飞轮二的待复习队列 |
| 沉淀 → 术语 | 背景摘要自沉淀时压缩保留"关键术语"（`generate_summary` 已有此约束） |

## 6. 分期路线

### 0.7（P0）

## 7. 风险与红线

| 风险 | 对策 |
|---|---|
| 自动沉淀污染用户手写的 summary | 只做"建议 + diff 预览 + 确认"，可全局关闭；绝不静默改写 |
| 方向识别误判导致整批解释口径错误 | 只做"轻提示 + 一键切换"，不静默变更学习方向；识别结果存 `source` 可追溯 |
| 建议清单变成推送轰炸 | 聚合视图 + 主动查看；托盘只提醒数字，不弹内容 |
| 三套词表归一的大改动 | 分阶段：先加画像层兼容三套输出，再逐步归一，不搞一次性重写 |
| 建议采纳率低（做了没人用） | 用 done/ignored 数据验证，1.0 前决定投入规模 |

## 8. 验收标准

- 方向识别：历史记录抽样人工标注，top-1 准确率 ≥ 80%；识别置信度与人工判断一致性抽样检查
- 学习建议：`learning_tip` 非空的记录 100% 落入 `learning_tips` 表；建议采纳率作为产品指标持续观察
- 自沉淀：背景摘要更新后人工抽查，覆盖最近增量中关键概念的比例 ≥ 80%
- 性能红线：方向识别为纯本地规则，单条 < 10ms；沉淀/建议均为手动或低频触发，不增加常态开销

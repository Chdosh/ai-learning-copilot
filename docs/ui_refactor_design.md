# AI Learning Copilot UI 重构设计文档

> 本文档提炼了开发过程中的全部 UI 讨论结论，作为后续 UI 重构（Phase 2/3）的执行依据。
> 配套后端已完成：`contexts` 表、`context_block` 提示词注入、领域/场景检测器（见 `docs/iteration_log.md` 2026-08-04 条目）。

## 0. 设计原则

- **分层**：紧凑弹窗（快看）↔ 主窗口工作台（深入）↔ 学习上下文（领域/场景定位）↔ 后期知识库（语义检索）。
- **主页面 = 概览**：用户打开主窗口第一眼进入核心入口和知识串联；统计摘要继续放在左侧底部，避免重复堆数据。
- **会话为核心**：每次截图/粘贴 = 一条"原文 → 翻译/解释 → 追问"的学习线程，工作台以会话为中心。
- **入口不重复**：截图入口只在 托盘 + 全局快捷键 + 概览页按钮（删除多余的"截图/小窗"页）。

## 1. 现状盘点与问题清单

原主窗口 7 页：首页 / 截图小窗 / 结果大窗 / 历史记录 / 术语本 / 数据统计 / 设置。

| 页面 | 问题 |
|---|---|
| 首页 | **Grid 布局 bug**：`本地 OCR` 与 `数据统计` 两张卡重叠在 `(1,1)`（`main_window.py` ~523/532）；"检查 OCR" 误跳统计页；纯静态卡片目录，无动态内容 |
| 截图/小窗 | 冗余：入口已在首页/托盘/快捷键多处存在，整页是说明页 |
| 结果/大窗口 | 最弱：纯 `_format_payload` 文本 dump，无结构 |
| 历史记录 | 详情无追问会话；无分页（limit 200 封顶）；无单条删除 |
| 术语本 | **假分页按钮**（`_chip("1")`、`_chip("20 条/页")` 点击无反应）；详情静态 ☆ 与收藏按钮重复 |
| 数据统计 | 职责混入：底部 6 个数据管理按钮（备份/恢复/清理/Anki/优化/信息）不该在这 |
| 设置 | 版本号不一致（UI `v0.2.0` vs pyproject `0.1.0`）；OCR 页 2 个"重新检测"+"2 个保存设置"冗余；字号不持久化 |

## 2. 冗余页判定与合并方案（7 → 4）

| 页面 | 处置 |
|---|---|
| 截图/小窗 | **删除**（入口已多处存在） |
| 结果/大窗口 | **合并**进"会话工作台"（它只是历史里最近一条的特例） |
| 首页 | **重构**为"学习概览" |
| 历史记录 | **进化**为"会话工作台"（列表 → 左栏；详情 → 中栏会话流） |
| 术语本 | 保留（修假 UI） |
| 数据统计 | 保留为详细看板（剥离数据管理） |
| 设置 | 保留（吸收数据管理 + 学习上下文管理） |

合并后 4 页，职责按"动词"归位不交叉：

```
学习概览 = 看（知识串联 + 核心入口）              ← 默认落地页
会话工作台 = 学（完整会话流 + 继续追问）          ← 深入
术语本 = 积（术语沉淀）
设置 = 配（AI/OCR/快捷键/学习上下文/数据/关于）
```

详细数据统计并入学习概览（简版）+ 设置（数据管理），不单独占主导航位。

## 3. 目标页面结构

```
侧边导航：学习概览 / 工作台 / 术语本 / 设置
侧边底部：统计摘要卡 + 导出 Markdown + A+/A-（保留现状）
托盘：截图翻译 / 显示主窗口 / 退出（不变）
```

> 决策（2026-08-05）：**职责对调**——「工作台」只保留新建学习入口（截图/文本双模式）；会话列表、会话流、上下文面板、追问全部移入「学习概览」页。

## 4. 学习概览页（会话视图，默认落地）

三栏会话视图 + 顶部学习上下文切换：

```
┌────────────────────────────────────────────────────────┐
│ 学习概览                                 [当前领域▾]      │
├────────────┬──────────────────────────────┬─────────────────┤
│ 左: 会话列表 │ 中: 会话流（核心）              │ 右: 上下文面板     │
│ [搜索]      │ 标题行: 标题/时间/分类/领域      │ 截图预览(点看原图)  │
│ [筛选chips] │ 原文(灰底)                     │ OCR原文(可复制)    │
│ ▣ 记录1     │ 翻译 → 解释 → 术语 → 学习建议    │ 术语列表(★收藏)    │
│ ▣ 记录2     │ 我: 追问1                     │ 标签·分类·领域     │
│ ▣ 记录3     │ AI: 回答1 (流式)              │ ──操作──          │
│ (滚动加载)   │ 我: 追问2                     │ 复制/弹窗/删除     │
│            │ AI: 回答2                     │                  │
│            │ [继续追问输入框][发送]           │                  │
└────────────┴──────────────────────────────┴─────────────────┘
```

- 左栏：历史记录搜索/筛选（全部/今天/本周/有追问）/缩略图/预览。
- 中栏：复用紧凑弹窗的渲染逻辑（同一套 HTML 渲染 + `FollowupWorker` 流式）+ 完整会话历史（`history_store.list_messages`）。
- 右栏：按当前 capture 取术语/截图/标签/操作。
- 顶部右侧：学习上下文切换器「当前领域：通用 ▾」（原概览工具条落点）。

## 5. 工作台页（识别入口 + 学习方向）

职责：发起一次新学习 + 设定解释方向。两个板块互不混淆：

```
┌─────────────────────────────────────────────┐
│ 工作台                                        │
│ 识别内容并按当前学习方向解释；方向决定解释领域… │
│ ┌─ 识别学习 ───────────────────────────────┐ │
│ │ [截图识别] [文本识别]                      │ │
│ │ 截图识别： [开始截图翻译]                  │ │
│ │ 文本识别： [多行粘贴框] [学习]             │ │
│ └──────────────────────────────────────────┘ │
│ ┌─ 学习方向 ───────────────────────────────┐ │
│ │ 当前：通用                                 │ │
│ │ [通用][编程][生物][医学][法律]             │ │
│ │ [金融][物理][化学][数学][社科]             │ │
│ │ [从摘要新建方向]                           │ │
│ └──────────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

- **识别学习**：截图识别 → 复用全局截图入口（`start_capture`）；文本识别 → 走同一条 AI 管线（`CaptureStreamWorker(source_text=)`），长文本触发"建议建立上下文"。
- **学习方向**：与"识别内容"是两个独立概念——预置方向（通用 + 检测器 9 个领域）一键切换；点击未创建的领域自动生成一个最简上下文并设为当前，已有则复用。当前方向高亮。
- 「从摘要新建方向」→ 打开 `ContextEditDialog`（粘贴摘要→自动检测→确认→设为当前），即"识别文字用于改变路径"的入口。
- 方向卡片下方有**当前方向详情窗**：显示当前上下文名称/领域/场景/背景要点/自定义说明（即导入的摘要内容）。
- 完成后结果在紧凑弹窗快速查看，并落库刷新到学习概览会话列表。
- 底部输入框支持**截图/文本双模式**（见 §8）。

## 6. 术语本 / 设置

### 术语本
- 表格：术语/中文名/关键词/次数/收藏 + 详情（解释/例子/收藏/编辑/删除）+ 搜索。
- **删假分页按钮**，改真分页或滚动加载。
- 静态 ☆ 并入收藏按钮。
- （后期）复习模式：按收藏/高频出复习卡。

### 设置（5 个子标签）
- **AI 配置**：key/base_url/model/测试连接（现状）。
- **OCR 状态**：只留 1 个"重新检测"，删冗余按钮。
- **快捷键**：输入 + 格式引导（`ctrl+alt+t`）。
- **学习上下文**（见 §8）。
- **数据管理**：备份/恢复/清理旧记录/导出 Anki/优化/数据库信息（从统计页迁来）。
- **关于**：版本号与 pyproject 统一；技术栈。

## 7. 知识串联（学习概览核心组件）

- **参考**：开源知识图谱项目（Learnify.AI 学生笔记图谱、NoteConnection DAG、Spine 彩色图谱）。
- **数据**：节点 = 术语（captures.tags/terms 字段）；边 = 术语在哪些截图中出现。
- **交互**：术语列表（带出现次数）→ 点击展开该术语出现的所有截图（时间/来源片段/跳转工作台）；分类同理。
- **实现**：Qt 用列表展开即可（不强制力导向图）；如需图，复用 `statistics_widgets.py` 自绘思路。

## 8. 学习上下文（领域 + 场景 + 背景锚点）

**定位**：解决"一个单词无法判断领域"的问题——用户先设定上下文，之后截图/粘贴都按该上下文解释。它也是应用通用化（不限于计算机）的关键。

### 概念
```
学习上下文 = 名称 + 领域(生物/医学/编程…) + 场景(学术论文/报错/界面…) + 背景要点(摘要关键词) + 自定义说明
提示词 = 通用基底 + 领域 + 场景 + 背景要点（已由后端 `render_context_block` 实现）
```

### UI 落点
| 位置 | 形态 |
|---|---|
| 设置 → 学习上下文子标签 | 上下文列表 + 新建/编辑/删除 + 设为当前 + 整理重复（完整管理） |
| 工作台 → 学习方向 | 预置基础领域 chips（通用 + 检测器 9 领域）一键切换 + 当前方向详情 |
| 学习概览顶栏 | 只读状态标签「学习方向：XX」 |

> 决策（2026-08-05）：**紧凑弹窗不做上下文切换**，只保留快速截图解释的最小功能；**概览页不放交互切换器**（避免被误认为历史筛选），只显示当前方向状态，切换统一收敛到工作台「学习方向」chips 与设置子标签。

### 新建上下文面板（粘贴摘要）
```
粘贴论文摘要
  → 本地检测建议：领域=生物、场景=学术论文、关键词=[CRISPR, 基因编辑…]
  → 用户确认/修改 领域、场景；填名称（可自动生成）
  → 可选：一键"生成背景摘要"（AI 把摘要压缩成几百字）
  → 保存为上下文，设为当前；渲染 context_block 写进 settings
```

### 关键规则
- 单词场景不做检测——上下文由用户提前设定。
- 长文本粘贴才做检测**建议**（只建议不强制）。
- `context_block` 为空 = 通用行为，与旧版完全一致。

## 9. 文本粘贴入口（= 模式切换入口）

- **工作台页**（见 §5）：截图/文本双模式切换（chips），文本粘贴走同一条 AI 管线 → 弹窗快速查看 + 落库进学习概览会话列表。
- 粘贴较长文本时，触发 §8 的"建议建立上下文"。

## 10. 已知 Bug 修复清单

1. 首页 Grid 重叠（`本地 OCR`/`数据统计` 同格）+ 跳转语义修正。
2. 术语本假分页按钮删除；静态 ☆ 合并。
3. 版本号统一（设置页跟随 pyproject）。
4. 设置 OCR 页冗余按钮清理。
5. 字号持久化（`ui_font_size` 写 settings，重启保留）。
6. 历史分页 + 单条删除；历史详情补会话展示。
7. FTS 中文分词（tokenizer=trigram，解决中文搜索）。
8. 历史"有追问"筛选精度（失败追问不建会话）。

## 11. 实施阶段

- **Phase 2（UI 系统重构）**：页面合并（§2-§6）、工作台三栏（§5）、学习概览 + 知识串联（§4/§7）、bug 修复（§10）。不动紧凑弹窗核心。
- **Phase 3（学习上下文 UI + 文本入口）**：设置子标签 + 概览页切换器 + 新建面板（§8）、文本粘贴入口（§9）。弹窗不加切换。
- **Phase 4（后期）**：embedding 语义搜索 UI、术语复习模式、知识库总结看台（叠加在概览之上）。
- **Phase 5（产品化）**：Windows 打包、字号持久化收尾、跨平台验证。

## 12. 文件归属（避免并行冲突）

- **Phase 2 主要动**：`main_window.py`、新增 `workbench.py`、`overview.py`、`knowledge_linking.py`、`statistics_widgets.py`。
- **Phase 3 主要动**：`settings` 子页、`context_switcher`、`main_window.py`。
- **共用文件**：`history_store.py`、`settings.py`——后端已就绪（contexts/context_block），UI 阶段只做读取，不再改数据结构。
